# DESIGN · Skills Registry

## Registered Skills

### UI Design

#### 1. `design.ui-component`
Design individual UI components — buttons, forms, cards, modals, tables, navigation elements.
- Input: component type, brand guidelines, design system tokens, use case, states (default/hover/active/disabled/error)
- Output: component spec with dimensions, colors, typography, spacing, states, responsive behavior

#### 2. `design.ui-layout`
Design page and screen layouts — grid systems, responsive breakpoints, content hierarchy, whitespace.
- Input: content inventory, user goals, device targets, brand constraints
- Output: layout spec with grid, breakpoints, content regions, responsive rules

#### 3. `design.ui-screen`
Design full screens and views — composition, visual hierarchy, information density, focal points.
- Input: user story, content, interactions, device, design system constraints
- Output: screen design spec with layout, components, states, transitions

### UX Design

#### 4. `design.ux-flow`
Design user flows and task journeys — entry points, decision trees, error states, completion paths.
- Input: user goal, entry point, success criteria, possible edge cases
- Output: flow diagram with screens, decisions, transitions, error recovery paths

#### 5. `design.ux-wireframe`
Create wireframes and low-fidelity prototypes — content structure, functional layout, interaction zones.
- Input: feature requirements, user stories, content, constraints
- Output: wireframes with annotations, interaction notes, content placeholder specs

#### 6. `design.ux-prototype`
Design interactive prototypes — click-through flows, state transitions, micro-interactions, feedback.
- Input: wireframes or design mockups, user flows, interaction patterns
- Output: prototype spec with screen connections, transitions, gesture handling, loading/empty/error states

#### 7. `design.ux-research`
Plan and conduct UX research — usability testing, user interviews, preference tests, analytics review.
- Input: research questions, user segments, current metrics, test materials
- Output: research plan with methodology, participant criteria, test script, success metrics

### Visual & Brand Design

#### 8. `design.visual-brand`
Develop and extend brand identity — color palettes, typography systems, logo usage, brand voice visualization.
- Input: brand name, industry, personality attributes, existing assets
- Output: brand identity spec with color system, type scale, logo guidelines, brand expression examples

#### 9. `design.visual-color`
Design color systems — primary, secondary, neutral, semantic palettes, contrast ratios, accessible combinations.
- Input: brand color(s), use cases (UI, data viz, alerts), accessibility target
- Output: complete color system with hex values, usage rules, contrast ratios, dark/light mode mappings

#### 10. `design.visual-typography`
Design typography systems — typeface selection, scale, hierarchy, line-height, responsive type.
- Input: brand personality, readability requirements, device range, language support
- Output: typography system with font selections, type scale, usage rules, responsive adjustments

#### 11. `design.visual-iconography`
Design icon systems — icon style, grid, sizing, semantic meaning, accessibility.
- Input: brand style, use cases (UI, data viz, illustrations), accessibility requirements
- Output: icon system spec with grid, style guide, sizing rules, accessible labeling requirements

#### 12. `design.visual-data-viz`
Design data visualizations — chart types, color encoding, labeling, accessibility, responsive layout.
- Input: data types, audience, use case (monitoring/reporting/exploration), brand constraints
- Output: data viz spec with chart type recommendations, color encoding, labeling, responsive rules

### Design Systems

#### 13. `design.system-tokens`
Define design token systems — color, typography, spacing, shadow, motion tokens with naming conventions.
- Input: visual foundations, platform targets (web, mobile), tooling requirements
- Output: design token spec with naming convention, token values, platform mappings, documentation

#### 14. `design.system-component-library`
Design component library architecture — component hierarchy, composition patterns, variant management.
- Input: application scope, existing patterns, technology stack, brand constraints
- Output: component library architecture with hierarchy, API patterns, variant matrix, documentation plan

#### 15. `design.system-documentation`
Create design system documentation — usage guidelines, component specs, code examples, contribution process.
- Input: component library, brand guidelines, development workflow
- Output: documentation site structure with component pages, usage guidelines, code snippets, contribution guide

### Interaction & Motion

#### 16. `design.motion-microinteractions`
Design micro-interactions — button feedback, hover states, form validation, notification animations.
- Input: trigger events, feedback type, brand motion guidelines, accessibility constraints
- Output: micro-interaction spec with trigger, animation, duration, easing, accessibility considerations

#### 17. `design.motion-transitions`
Design screen and element transitions — page transitions, modal entrances, list reordering, loading sequences.
- Input: navigation model, content types, performance targets, brand style
- Output: transition spec with trigger, animation type, duration, easing, shared element mapping

#### 18. `design.motion-loading`
Design loading and progress states — skeleton screens, progress indicators, optimistic UI, delayed feedback.
- Input: data loading patterns, expected durations, criticality, performance constraints
- Output: loading state spec with skeleton designs, progress patterns, timing rules, error handling

### Accessibility

#### 19. `design.a11y-color`
Audit and improve color accessibility — contrast ratios, color blindness considerations, semantic color usage.
- Input: color system, usage contexts, WCAG target level (AA/AAA)
- Output: color accessibility report with violations, recommendations, alternative palettes

#### 20. `design.a11y-interaction`
Design accessible interactions — keyboard navigation, focus management, screen reader support, touch targets.
- Input: interaction patterns, platform, accessibility target
- Output: interaction accessibility spec with keyboard commands, focus order, ARIA patterns, touch targets

#### 21. `design.a11y-audit`
Conduct accessibility audits — WCAG compliance check, automated testing, manual review, user testing with assistive tech.
- Input: screens or components, WCAG target level, audit scope
- Output: accessibility audit report with violations by severity, remediation steps, testing evidence

### Design Operations

#### 22. `design.ops-workflow`
Design design workflows — handoff processes, review cycles, file organization, version control.
- Input: team size, tools, project types, collaboration requirements
- Output: design ops workflow spec with toolchain, file structure, review process, handoff guidelines

#### 23. `design.ops-critique`
Facilitate design critique sessions — framing, feedback guidelines, action tracking, iteration cycles.
- Input: design work, critique goals, team experience level
- Output: critique session plan with framing questions, feedback format, action items, follow-up process

#### 24. `design.ops-design-sprint`
Plan and run design sprinds — problem framing, ideation, prototyping, user testing, decision frameworks.
- Input: challenge statement, stakeholders, timeline, success criteria
- Output: sprint plan with daily schedule, methods, facilitation guides, decision framework
