## 1. WHAT IS EMPIRE AI V49?

Empire AI V49 is a predictive-revenue / lead-generation automation platform. It runs a mesh of autonomous agents (bots) that:
- Score inbound leads (`predictive_revenue.py`)
- Place outbound Vonage calls with TTS scripts (`empire_voice.py`, `voice_streaming_agent.py`)
- Synthesize audio via Kokoro TTS (`synthetic_brain.py`)
- Stream PCM over WebSocket to live phone calls (`/api/v1/synthetic/stream`)
- Track per-lane MRR + LLM narrative + adaptive calibration (`predictive_revenue.py`)
- Run an AGI governor for lane prioritization + watchdog (`empire_agi_governor.py`)
- Serve a Cinematic Command Deck SPA (`empire_command_spa.py`, ~4600 lines)
- Connect to Supabase for persistence + Anthropic-style JSON-schema-constrained LLM calls (local Ollama, default `llama3.2:3b`)

**Stack:**
- Backend: Python 3.10+, FastAPI, Supabase, httpx, numpy, soundfile, kokoro-onnx
- Frontend: single-file React SPA via esm.sh CDN imports (no build step)
- Voice: Vonage Voice API (`stream` NCCO action for WebSocket audio)
- Infra: Hetzner Cloud (cx22, Ubuntu 22.04, Caddy or Nginx + certbot)
- LLM: local Ollama (default `llama3.2:3b`); grammar-constrained via JSON Schema

**Project scale:** ~40,000 lines of Python across 19 biggest files; ~50 commits in last 6 months.

## 11. KEY DESIGN DECISIONS

### StreamRegistry abstraction
- Same `set/get_and_delete/sweep_expired` API for both backends so call sites are backend-agnostic
- In-memory: `ttl_seconds` is stored as `registered_at` metadata; `sweep_expired()` checks against it
- Redis: `SETEX` handles TTL automatically (no manual sweep); `GETDEL` is atomic
- Wall-clock TTL check in `_pop_stream` catches in-memory entries that haven't been swept yet (safe no-op for Redis via the `registered_at is not None` guard)

### Terraform DNS provider
- Used `germanbrew/hetznerdns` (community, v3.0) because the official hcloud provider explicitly refuses DNS (open issue #183)
- Marked deprecated as of November 2025; will need to migrate if/when Hetzner ships DNS in the official provider

### Reverse proxy choice (Caddy vs Nginx)
- Both snippets exist in `deploy/hetzner/`
- Caddy is recommended (auto-TLS, no certbot dance) but Nginx is offered for teams that already have certbot workflows

### Orchestrator wrapper location
- `bots/synthetic_brain.py` is the correct location because main.py's pattern is `importlib.import_module("bots.{name}")`
- The wrapper does `import synthetic_brain` (bare) to import the FastAPI app, with PROJECT_ROOT in sys.path

### Fail-closed env-var guards
- Every startup script (deploy/hetzner/start_*.sh, bots/synthetic_brain.py, deploy/hetzner/scripts/first-boot.sh) refuses to start if required env vars are missing
- Uses `set -euo pipefail` + `: "${VAR:?msg}"` pattern

### Migration auto-discovery
- `glob.glob("migrations/*.sql")` + `sorted()` ensures NNN-prefix ordering is preserved
- Explicit `args` override (so `python3 scripts/run_migrations.py migrations/005_new.sql` still works)
- Behavior change: old default ran only 001+002; new default runs ALL migrations (documented in docstring)

### scripts_archive/ convention
- All one-off diagnostic/fixup scripts (analyze/fix/debug/check/diag/find/transform/refactor/validate/patch/apply) live in `scripts_archive/`
- README at `scripts_archive/README.md` documents which patterns are archived + which scripts stay active
- `git mv` was used to preserve history
